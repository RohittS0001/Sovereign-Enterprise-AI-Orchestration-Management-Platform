# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Sovereign (self-hosted, local-LLM) enterprise agentic AI platform for project/delivery management.
FastAPI backend in `backend/app` (domain modules — see `docs/architecture.md`), React frontend in
`frontend/`. An agent answers questions by calling governed tools over Jira, GitHub, Keka, Gmail, the
knowledge base and project analytics, with human approval for writes, RBAC and a hash-chained audit log.

Work proceeds in phases, one local commit each (never push unless asked). Done: 1–7 (foundation,
auth/RBAC, agent + approvals + audit + guardrails, GitHub/Keka/Gmail drafts + demo mode, RAG, analytics
+ reports + quotas, React frontend), the domain restructure, 8 (evaluation + observability), 9
(Docker Compose, CI, Helm, README) and 10 (connection registry, MCP code mode, digital twin, all of
Backlog A and B except LoRA fine-tuning, RAG/planning evals) and most of Backlog C (delivery lifecycle).
Remaining work: the rest of Backlog C (intake portal, staffing, standup digest, lessons library, enterprise readiness).
`docs/ROADMAP.md` is the backlog source of truth (integrations, moonshots, lifecycle features) — tick
items there as they land.

npm --prefix frontend run dev                     # UI on :5173, proxies /api to :8000

.venv/Scripts/python.exe -m uvicorn backend.app.main:app --reload
.venv/Scripts/python.exe -m alembic upgrade head

- Adding/changing an integration's settings: update `.env.example` and run
  `python -m scripts.connections --markdown` (regenerates `docs/integrations.md` and the
  `connections.env.example` template) — `tests/unit/integrations/test_connector_registry.py` fails if
  any is stale. Settings load `.env` then `connections.env` (git-ignored, one file for every
  integration's links/keys; `--init` creates it).
- Bash heredocs with quotes/backslashes often break in this Git Bash; write multi-line edits as a
  Python script file (scratchpad) or use the Edit tool. Avoid `# fmt: skip` on long lines (E501).

- Run Alembic as `python -m alembic` (invoking `alembic.exe` directly is denied). Target a scratch DB
  with `-x url=sqlite:///path/to.db`. `tests/integration/db/test_database.py` runs `alembic check`, so
  every model change needs a migration (hand-tune autogenerated ones, e.g. data seeds, custom types).
- Exact runtime pins live in `requirements.txt`, dev/test tools in `requirements-dev.txt` (which
  includes it); ranges in `pyproject.toml` — update both when adding deps.
- `tests/integration/postgres/` (marker `postgres`) runs only with `TEST_POSTGRES_URL` set to a
  disposable pgvector database; CI provides one. They cover migrations + `alembic check`, pgvector
  hybrid search and the audit chain on real PostgreSQL.
- Frontend: Windows Application Control on this machine blocks Rollup's native binary, so
  `frontend/package.json` overrides `rollup` with `@rollup/wasm-node`. Keep that override.
- `.pre-commit-config.yaml` runs ruff, a secret-file blocker and the frontend type check.

## Architecture (paths relative to `backend/app/`)

Dependency direction: `api` → `domains`/`tools` → `integrations`/`llm` → `core`/`db`. Integrations
never import domains. `db/models/__init__.py` is the registry that imports every domain model (Alembic,
tests, and `from backend.app.db.models import X` all rely on it) — register new models there.

**App factory.** `main.py:create_app(settings, database, *, agent_models, tool_registry)` builds
everything onto `app.state` (settings, database, rate_limiter, agent_models, tool_registry,
integrations, embedder, reranker, analytics_collector, report_scheduler). Routers in `api/v1/` get them
via `Annotated` deps in `api/deps.py` (`SessionDep`, `DatabaseDep`, `PrincipalDep`,
`require_permissions(...)`, …). Injected resources are not disposed on shutdown.

**Request pipeline.** `core/middleware/request_context.py` (outermost) sets the request-ID contextvar
(`core/context.py`), logs access, and turns unhandled exceptions into a 500 that keeps the ID →
security headers → CORS → routers. Raise `AppException` subclasses from `core/errors.py` (not
`HTTPException`); `core/error_handlers.py` renders `{"error": {code, message, details, request_id}}`.
JSON logs via `core/logging.py`. Settings: `core/config.py` (`get_settings()` cached; module-level
`settings` used as client defaults).

**Auth & permissions** (`core/security/`, `domains/identity/`). Short-lived JWT access tokens + hashed
refresh tokens rotated on each use (replay revokes all sessions). Permissions come from the user's
*current DB role* each request. The agent acts as `principal.as_agent()` = user permissions ∩
`AGENT_SCOPES`; `APPROVAL_REQUIRED` marks agent writes that need a human.

**Agent** (`domains/agent/`, `POST /api/v1/agent/query[/stream]`). `service.py` creates an `AgentRun`
and streams `graph.py`: `nodes/planner.py` (LLM 1, `llm/structured.py:generate_structured` →
`PlannerOutput`) → `nodes/executor.py` → back to planner until done/budget → `nodes/verifier.py` →
`nodes/responder.py` (LLM 2, `[S1]` citations filtered to successful steps). Prompts in `prompts/`.
`observations.py` compacts tool results (drops noisy keys, flattens ADF); they're redacted, truncated,
injection-scanned and wrapped in `<untrusted_data>` before any model sees them. `run(on_event=...)`
feeds the SSE stream (`run_started` → `step`* → `phase` → `done` | `error`); the stream endpoint uses
its own DB session in a task and finishes even if the client disconnects.

**Tool chain — follow it for every new integration:**
1. `integrations/<x>/client.py` — subclass `integrations/common/http.py:HttpIntegrationClient` (errors →
   `IntegrationError` with upstream status, empty 201/204, rate-limit waits for GETs, `_auth_headers` /
   `_on_unauthorized` hooks as Keka uses). Accept `transport` for tests.
2. `integrations/<x>/service.py` — validate identifiers used in URLs/queries, trim payloads (drop
   personal data), build the client lazily via `client_factory`.
3. `tools/<x>/schemas.py` — Pydantic input models (the JSON schema the planner sees).
4. `tools/<x>/tools.py` — wrap calls in `tools/runner.py:run_tool`; **never raise**, return
   `tools/base.py:ToolResult` (retryable for timeouts/429/5xx). Blocking SDKs via `asyncio.to_thread`.
5. `integrations/hub.py:build_integration_hub(settings)` — add the service when configured, with a
   `client_factory` from *the given* settings, plus a health check; register in `tools/catalog.py` as
   `<integration>.<operation>` with description, `input_model`, READ/WRITE and a `Permission`.
6. Add an in-memory twin in `integrations/demo/services.py` (+ `demo/dataset.json`, dates as `{today±N}`).
7. `tools/registry.py` does validation, timeouts, read-only retries; `tools/gateway.py` enforces
   permission → validation → approval → execution, audits every outcome, commits after each call, and
   sets `core/context.py:principal_var` so per-user tools (knowledge, analytics) know who is asking.

**Governance** (`domains/governance/`). `approvals/service.py`: approving executes the stored call and
settles the run (agent not re-run); approver needs `approvals:decide` *and* the action's permission;
optional four-eyes, TTL, `APPROVAL_EXEMPT_TOOLS` (ignored once a run is injection-flagged).
`audit/service.py`: SHA-256 hash-chained events written *in the caller's transaction* after locking
`audit_chain_head` — commit promptly; action names in `audit/actions.py`; never update/delete events.
`guardrails/`: `redact_text`/`redact_data` (secrets, cards, Aadhaar, PAN, SSN, IBAN; contact info
optional) and heuristic `scan_for_injection`.

**Knowledge** (`domains/knowledge/`, agent tool `knowledge.search`). `parsers.py` → `chunking.py` →
`embeddings.py` (Ollama/OpenAI-compatible or offline `HashingEmbedder`) → `Document`/`DocumentChunk`
(SHA-256 dedup). Search: dense + BM25/full-text (title field-boosted; `search_terms` keeps identifiers
like `PHX-7`/`#103` whole and folds plurals) → `ranking.py` **weighted RRF** (`fusion_params`: auto k=60/
weights 1:1 with a real embedder, k=5/semantic 0.1 with the hashing embedder — tuned with the retrieval
eval; `RAG_RRF_K`, `RAG_*_WEIGHT` override) → `exact_match_first` (records titled with a queried ID
first) → per-document cap → optional `reranker.py`. `SearchFilters` (sources, project, since/until) and
**access control are SQL `WHERE`s applied before ranking** (roles stored as `",role,"` for a portable
LIKE). `indexing.py` indexes every connected platform per project (Jira+history+comments, GitHub PRs/CI,
other trackers, Slack/Teams channels from `Project.links` `slack_channels`/`teams_channels`, e-mail,
incidents/errors/deploys, meetings, leave, finance, CRM) as documents with `project_key`/`occurred_at`;
each item's permission (`roles_with`) becomes its role list; incremental by checksum; a failing source
keeps its documents. `POST /api/v1/knowledge/index`, `scripts.sync_documents --projects`. PostgreSQL
path (pgvector `<=>`, `ts_rank_cd` with a weighted title) not yet run on live PG.

**Analytics & reporting** (`domains/analytics/`, `domains/reporting/`, `/api/v1/projects/{key}/health`).
`Project` links a Jira key to repos, active sprint and members (Jira ↔ Keka ids, capacity).
`collector.py` fetches once (TTL cache; pass `today=` in tests) into `snapshot.py` facts; failing
sources become warnings. Pure functions: `forecast.py`, `workload.py`, `contradictions.py`, `risk.py`.
`reporting/generator.py` (LLM 2 narrative over untrusted-wrapped metrics, template fallback) and
`reporting/scheduler.py` (lifespan task, unique-constraint dedupe). `domains/usage/service.py` computes
usage and enforces `AGENT_DAILY_TOKEN_QUOTA`.

**Evaluation** (top-level `evaluation/`, see its README). `environment.py` builds an isolated seeded
instance (in-memory DB, demo integrations, a user per role, demo docs, PHX from
`integrations/demo/seed.py` — the single source of demo seed data). Formulas in `evaluation/metrics.py`
(+ `judges.py` LLM-as-judge, `frameworks.py` Ragas/DeepEval export); guide in `docs/evaluation.md`. Suites in `evaluation/suites/`
read `evaluation/datasets/*.yaml` (data + thresholds): retrieval (incl. leak rate), guardrails,
analytics (golden values at a fixed date), delivery (synthetic sprints with planted delay causes),
platform_search (hybrid search over all indexed sources, filters, permission leaks), redteam (scripted hostile planner through the real
`AgentService`/gateway), agent (real model; optional LLM-2 judge fed the exact responder prompt via a
recording wrapper). `tests/evaluation/test_quality_gates.py` enforces the offline suites in CI and
proves they fail when approvals, access control or redaction are broken — keep that property when
adding suites. When a behaviour change shifts a golden value, update the dataset deliberately.

**Observability** (`core/observability.py`, `api/metrics.py`). Prometheus counters/histograms for
HTTP (labelled by route *template*; unknown paths → `unmatched`), agent runs, tool calls, LLM
latency/tokens, rate limits and approvals, exposed at `/metrics` (`METRICS_TOKEN` optional). Tracing
via OpenTelemetry: spans for each request, `agent.run`, `tool.invoke` and `llm.request`; exported only
when `OTEL_EXPORTER_OTLP_ENDPOINT` is set (otherwise no-op). Logs include `trace_id` when tracing.
Use `core.observability.span(...)` for new spans instead of creating tracers.

**LLMs** (`llm/`). `OllamaClient`, `OpenAICompatibleClient`, `FakeLLM`; `AgentModels(operations,
reporting)` from `llm/factory.py`. No `LLM1_MODEL_NAME` → agent endpoints return 503.

**Deployment** (top-level `deploy/`, `docker-compose.yml`, `.github/workflows/ci.yml`).
`docker/api.Dockerfile` (non-root uid 10001; `entrypoint.sh` migrates, optionally seeds the demo via
`scripts.run_demo --seed-only`, then uvicorn), `docker/web.Dockerfile` (nginx template proxying `/api`
to `${API_UPSTREAM}`, SSE unbuffered, `/metrics` blocked). Compose: db + api + web by default, profiles
`ai` (Ollama) and `monitoring` (Prometheus, Grafana with provisioned dashboard, Jaeger).
`helm/sovereign`: external Postgres, secrets from `existingSecret`, migrations as a pre-install/upgrade
hook Job, optional Ingress/HPA/ServiceMonitor. CI: backend (ruff, pytest incl. Postgres service, eval
reports), frontend (types, Vitest, build), then image builds, compose config and `helm lint`. None of
Docker/Helm is runnable locally — CI is the only check.

**Connectors** (`integrations/connectors/`) — the pattern for every integration beyond the core four.
`spec.py:ConnectorSpec` (required/optional Settings fields → env vars, setup hint, docs URL, `build`,
`demo`); `registry.py` lists them all (`CONNECTOR_SPECS`, `ALL_SPECS`); settings live in
`core/connector_settings.py` (a `Settings` mixin). `base.py`: `ConnectorClient` (HttpIntegrationClient +
token-provider auth, `get_bytes`/`get_text`), `ConnectorService` (lazy client), `safe_id`, and common
models (WorkItem, PullRequest, Incident, ErrorGroup, Deployment, QualityGate, LeaveRecord, BudgetLine,
Deal, CalendarEvent, Transcript, SourceDocument). `auth.py`: OAuth client-credentials/refresh tokens,
Microsoft/Zoho/Google helpers. Category modules: `trackers`, `ops`, `hr_finance`, `crm`, `docs`,
`calendar_meetings`, `chat`, `cloud` (AWS via in-house SigV4 in `auth.py:aws_sigv4_headers` — tagging API
inventory, EC2/EBS/RDS/S3 details, CloudWatch alarms, opt-in cached Cost Explorer, Security Hub; Azure via
Resource Graph KQL, Cost Management, Alerts; resources belong to a project by the `CLOUD_PROJECT_TAG_KEY`
tag = key or `links.cloud_tag_values`). `domains/cloud/service.py` (`project_cloud`, `portfolio`;
security findings only with `audit:read`), `api/v1/cloud.py` (`/projects/{key}/cloud`, `/portfolio`). Hub: `hub.connectors` + `hub.by_category(cat)`; `build_integration_hub(
settings, demo_today=...)` (pin `demo_today` in tests/evals). Category tools in `tools/connectors.py`
(`tracker.*`, `ops.*`, `hr.list_leave`, `finance.budget_vs_actual`, `crm.list_deals`, `calendar.*`,
`meetings.*`, `chat.post_message`) fan out over sources with per-source warnings. Mocked-API tests use
`tests/support/connectors.py:MockApi`; demo data in `integrations/demo/connectors.json`.

**Phase 10 features.** `domains/mcp/` (code mode: `sandbox.py` AST interpreter — never exec;
`codemode.py` over ToolGateway as `principal.as_agent()`; `server.py` JSON-RPC; `api/v1/mcp.py`,
`scripts/mcp_stdio.py`; tokens in `identity/token_service.py`, MCP-only). Analytics: `twin.py`
(Monte Carlo), `negotiation.py`, `evm.py`, `predictive.py` + `ProjectSignal`, production/commitment/
budget risk factors (only when that data exists); `Project.links` scopes ops/finance per project;
members may carry `hr_employee_id`/`github_login`. `domains/knowledge/sync.py` (restricted → admin-only),
`domains/meetings/actions.py`, `domains/chat/` + `api/v1/chat.py` (Slack/Teams, signature-verified,
background tasks on `app.state.chat_tasks`), `domains/graph/`, `domains/briefing/` (chief of staff +
voice script), `domains/compliance/`, `domains/agent/team.py` (supervisor + tool-subset specialists).

**Delivery lifecycle** (`domains/delivery/`, `api/v1/delivery.py`, tools `delivery.*`). Pure functions over
the analytics snapshot: `roadmap.py` (list scheduling — one task per person at a time — then CPM slack and
critical path; cycles broken and reported), `dora.py` (bands per DORA; non-prod deploys excluded; MTTR from
`Incident.resolved` via `incident_history`), `release.py` (release notes, retrospective with optional LLM 2
summary over untrusted-wrapped facts), `backlog.py` (requirements → epics/stories via LLM 2 or an offline
parser, estimates from similar issues, submitted as `jira.create_*` through the gateway = approvals only).
`delay.py` ("Why is it late?"): Jira changelog + comments + e-mails (only with `email:read`) → person-days
lost per cause; blocked time follows "blocked by" links to the root cause (external if notes mention a
vendor/partner); claims in comments/e-mails ("on track", "no blockers", "done by <date>") are checked
against the data *on the day they were said*. Product focus: one owner sees the real reason a project is late.

**Database** (`db/`). Async SQLAlchemy 2; PostgreSQL in prod, SQLite in tests. `db/types.py`:
`UTCDateTime` (always tz-aware UTC — applied to every `datetime` via `Base.type_annotation_map`) and
`EmbeddingVector` (pgvector on PG, JSON elsewhere). Enums are non-native strings with `values_callable`.

**Frontend** (`frontend/src/`). `shared/api/client.ts` (access token in memory, refresh token in
sessionStorage, one refresh-and-retry on 401, `ApiError`), `shared/api/stream.ts` (SSE via fetch),
`shared/auth/`, `shared/ui/`; pages in `features/<area>/`. Routes gated by `user.permissions`.

## Testing conventions

- Layout mirrors the code: `tests/unit/<area>/`, `tests/integration/{api,agent,db,live}/`, shared fakes
  in `tests/support/` (`agent.py`: real tool catalog over mocked services + scripted `FakeLLM`s;
  `analytics.py`: the PHX project config).
- `asyncio_mode = "auto"`, `--import-mode=importlib`; import helpers as `from tests.conftest import ...`.
- Fixtures (`tests/conftest.py`): `test_settings` (ignores `.env`, in-memory SQLite, fixed JWT secret),
  `database`, `client` (httpx `AsyncClient` + lifespan via `serve(app)`), `make_user(role=...)`,
  `auth_headers(user)`, `TEST_PASSWORD`. Don't use FastAPI `TestClient` (different event loop).
- Use `example.com` emails (`email-validator` rejects `.test`/`.local`). Ruff runs bandit `S` rules:
  constants that merely look like secrets need `# noqa: S105`.

## Environment cautions

- Repo root holds gitignored `.env`, `credentials.json`, `token.json` with the user's **real** Gmail token
  and Jira credentials. Don't read them; never let tests or smoke runs reach real services (override
  `JIRA_*`, `GMAIL_TOKEN_FILE`, `GMAIL_CLIENT_*`; point `LLM_BASE_URL`/`JIRA_BASE_URL` at stand-ins).
- The user may be running the demo themselves (ports 8000/5173). For smoke runs use another port
  (`PORT=8011`) in a Terminal tab you own and stop that tab — never kill processes by name.
- No Docker, PostgreSQL or Ollama on this machine; Postgres is verified via `alembic upgrade head --sql`.
